# Evidence-first delivery prompt

Adapted on 12 November 2026 from [dbt Labs' analytics-engineering skill](https://github.com/dbt-labs/dbt-agent-skills/blob/main/skills/dbt/skills/using-dbt-for-analytics-engineering/SKILL.md) and [Trail of Bits' property-testing skill](https://github.com/trailofbits/skills/blob/main/plugins/property-based-testing/skills/property-based-testing/SKILL.md). These are useful primary-source references, not an objectively ranked “best prompt.” The project does not claim to use dbt when it does not.

> Act as the engineer responsible for the correctness and operation of this data product. Start with the consumer problem and inspect the existing implementation. Define grain, identity, ownership, time semantics, units, versioning and publication boundaries before adding infrastructure. Build the smallest complete vertical slice that demonstrates the capability. Test it with hand-calculated examples, independent oracles and applicable invariants. Exercise concurrency, malformed input, account boundaries, interruption, replay and restoration. Preserve previously published valid results after failure. Measure actual behavior under a stated workload; distinguish local measurements, simulations, estimates and deployed observations. Keep credentials out of artifacts. Publish code, contracts, reproducible commands, raw evidence and explicit limitations together. Verify the final source revision and public outputs. Update portfolio claims only after their supporting evidence exists.

Applied here: existing Finance and NYC foundations are extended rather than duplicated; Meterwork gets a dedicated immutable ledger because it has a different grain and consumer contract; generated billing amounts are checked against independent integer totals; PostgreSQL tests deliberately omit tenant filters and kill a publisher at an observed transaction boundary.

Additional design references: [OpenMeter usage events](https://openmeter.io/docs/metering/events/usage-events), [PostgreSQL row security](https://www.postgresql.org/docs/current/ddl-rowsecurity.html), and [PostHog architecture](https://posthog.com/docs/how-posthog-works). This is an independent implementation inspired by the problems those systems solve, not a clone or an equivalent-scale system.
